# Rubric: is this pull request ready to submit?

Every check reads the artifact itself (the diff, the test output, the description) against the plan, the issue, and the repo's stated standards. Length, polish, and confident wording earn nothing. A terse PR with a matching diff and decisive evidence is ready. A beautiful one hiding drift, untested behavior, or debris is not. A PR that honestly discloses a shortfall in both the plan's deviation notes and the description can be ready.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | Every changed file and hunk in the diff, read against the plan's scope pair (in scope / not in scope), its approach, and its deviation notes. | Every change in the diff falls inside the plan's scope or is explained in a deviation note, and every change the plan promised is in the diff or is explicitly deferred in a deviation note and in the description. Fail if the diff adds anything the plan does not cover (a new option or flag, a rewrite, a rename pass, an extra file) with no deviation note, or touches something the plan scopes out. Fail if a promised change (for example a docs update) is missing with no disclosed deferral. | required |
| description-faithful | The PR description's claims about what changed ("implements the plan exactly", "no changes beyond", "the docs now document", its list of changes), read against the diff. | Every claim the description makes about the change is true of the diff, and its list of changes matches the hunks that are actually there. Fail if the description claims fidelity the diff contradicts, claims a change the diff does not contain, or leaves out a change the diff does contain. | required |
| evidence-decisive | The test evidence section, read against the plan's test plan and the issue's reproduction steps. | The evidence re-runs the plan's test plan or the reproduction on the path the fix changes and shows an observable before and after (output, exit code, assertion, or log value). If the plan's test plan names more than one case, each one is shown or its absence is disclosed. Fail if the evidence is only "tests pass", "works on my machine", or "verified locally" with nothing observable, or if it exercises only a control path or a different path than the one the fix changes. | required |
| repo-checks-run | The test evidence and description, read against the checks the repo's PR template or contributing guide names (its test suite, lint, format, or typecheck commands). | The repo's own test suite or named checks were run on the change and their outcome is visible: a named command and its result, or an honest note saying which check could not run and why. Fail if the repo names a suite or checks and the PR never shows them being run. | required |
| diff-clean | The unified diff and the commit list. | The diff contains only the change and what directly supports it (its test, its changelog entry). Fail if it carries debris: debug prints or logging left in, commented-out code or earlier attempts, dead functions, TODOs unrelated to the fix, formatting or import churn on untouched lines, or unrelated hunks. | required |
| template-honored | The repo-facts PR template and contributing asks, read against the description and the diff. | Every section the PR template requires is filled with real content, and every stated ask is met: the issue linked when the template or guide asks for it (for example "closes #" or "fixes #"), a required checklist answered, and a required changelog or release-note entry present in the diff. Fail if a required section or ask is visibly ignored. If the repo has no template and no stated asks, this check passes. | required |
| ai-disclosure | The repo-facts contribution policy (any AI policy), then the PR description. Treat every package as AI-assisted work. | If the repo's stated policy requires disclosing AI use in pull requests or in all contributions, the description discloses it, naming the tool and how it was used. If the repo has no AI policy, a permissive one with no disclosure ask, or only an own-words rule for comments, this check passes. Fail only when disclosure is required and the description does not disclose. | required |
| commits-readable | The commit list. | Commit messages say what each commit does, not "wip", "fix", or "misc". | preferred |

## Verdict rule

Accept if every required check passes. Reject if any required check fails or is unclear: a claim I cannot verify from the package is not ready to submit. The preferred check is reported but never changes the verdict.
