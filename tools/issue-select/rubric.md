# Rubric: is this a good first issue?

All dates are measured against the bundle's capture date in eval mode, and against today in live mode. "Maintainer" means an author shown as OWNER, MEMBER, or COLLABORATOR.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| repo-alive | The `archived:` field on the repo line. The dates and authors in "last 5 default-branch commits" (live: the repo front page and its commit list). | Passes if `archived: no` AND at least one of the last 5 default-branch commits is dated within 180 days of the capture date. That commit must be authored by a human, or be a bot merging a human's pull request (for example "kubernetes-prow[bot]: Merge pull request #N from <user>/..."). Commits that are bot-authored with no human PR behind them (dependabot bumps, pre-commit autoupdates) do not count. Fails if the repo is archived or the newest qualifying commit is more than 180 days old. A missing release does not fail this check. | required |
| not-claimed | The "this issue: assignees" and "linked PRs" lines in Repo facts; the issue's labels; every comment in the Comments section (live: the Assignees and Development sidebar boxes, the labels, and the thread). | Fails if ANY of these is true: (1) assignees is not `none`; (2) any linked PR is `(open)`, or a comment links or mentions a PR for this issue that is open or in review; (3) the issue carries an `in progress` (or similar "claimed") label; (4) a non-maintainer posted a claim comment ("I'll take this", "can I work on this", "working on it", "I've opened a PR") within the last 60 days and no maintainer later said the issue is free. PRs marked `(closed)` or `(merged)` are not claims. A claim comment more than 60 days old with no open PR is stale and does not block. Otherwise passes. Live mode: apply scope.md's Path Review house rule, under which classmates' claim comments do not block. | required |
| scope-bounded | The issue title and body, the labels, who opened it (author association), the full comment thread, and the count and state of linked PRs. | Fails if ANY of these is true: (a) **Umbrella:** the issue calls itself a tracking, umbrella, meta, or "megaissue", OR its body lists several separate sub-tasks meant to become separate PRs (a checklist of files or steps that together make ONE PR is not an umbrella), OR it asks for a change applied across the whole codebase (for example "add type hints everywhere"). (b) **Unsettled design:** the thread shows people still debating what the behavior should be, with no maintainer comment stating the agreed approach; OR the issue has been open more than 1 year AND has 2 or more closed-unmerged PRs. (c) **Core internals:** a maintainer says the fix requires deep or architectural changes. (d) **Support question:** it is a "how do I…" usage question, not a requested change. (e) **Unendorsed feature wish:** it asks for a new user-facing feature AND no maintainer has endorsed it (not opened by a maintainer, no maintainer-applied `good first issue` / `help wanted` / accepted label, and no maintainer comment agreeing to it), OR it leaves key product decisions open ("TBD", "asset TBD", "not sure what it should do"). Passes when the work is a single bounded bug fix, docs change, or endorsed feature. A short body or a missing reproduction does not fail a bug or docs issue on its own. | required |
| ai-policy-allows | The "contribution policy" line in Repo facts (live: CONTRIBUTING.md, its linked contributor docs, and any AI_POLICY.md or AI_USAGE_POLICY.md file). | Fails only if the policy bans AI-generated contributions outright (for example "we do not accept AI-generated code or documentation"). Passes when the policy states conditions instead: disclosure, the contributor must understand and test every change, human review, or "fully AI-generated not accepted, assistive use allowed." Also passes when the repo says nothing about AI or has no CONTRIBUTING.md. An AGENTS.md file is a pass signal. | required |
| maintainer-responsive | The "maintainer first-response sample" in Repo facts, plus maintainer comments in this issue's thread. | Passes if at least 1 sampled issue got a maintainer first response within 14 days, OR a maintainer commented in this issue's thread within the last 90 days. | preferred |
| newcomer-label | The issue's labels. | Passes if the issue carries `good first issue`, `help wanted`, `easy`, or an equivalent newcomer label. | preferred |
| recent-release | The "latest release" line in Repo facts (live: the Releases box). | Passes if the latest release is dated within 365 days. | preferred |

## Verdict rule

Accept if and only if every **required** check (repo-alive, not-claimed, scope-bounded, ai-policy-allows) grades `pass`. Any required `fail` rejects. **Preferred** checks never change the verdict; they only rank accepted issues, and more preferred passes rank higher.

How to treat `unclear`:
- On repo-alive, not-claimed, or scope-bounded, `unclear` counts as **fail**, because a first issue you cannot verify is not one to take.
- On ai-policy-allows, `unclear` (no policy found) counts as **pass**, because silence is not a ban.
